Student Record Management System (SRMS): Python, JSON, and a Problem That Needed Solving

Python · JSON · CLI

The Student Record Management System started right after my 11th final examinations ended.

For most of 11th grade, I had been balancing school academics, JEE preparation and Computer Science together, so I intentionally avoided starting any major project. I knew that once I became deeply involved in building something, it would consume most of my attention.

But the idea had already been sitting in my head for months.

The project was built entirely in Python and designed to run completely through the terminal. The goal was straightforward — create a system capable of storing, managing and presenting student records in a structured way.

Initially, I considered using MySQL for data storage because that was the conventional approach. I already understood basic SQL concepts, but I didn't know how to integrate MySQL with Python properly. Instead of spending time learning database integration, I chose to use JSON files as the storage system.

That decision made the project far more challenging than I originally expected.

Since JSON files don't naturally behave like databases, almost everything had to be handled manually — record structure, updates, validation, searching and overall data consistency. I spent a huge amount of time thinking about how the internal structure of the system should behave instead of just focusing on visible output.

As development progressed, the project slowly became less about completing a school-level program and more about designing a proper system.

I started thinking through concepts like separation of concerns, code readability, scalability of the structure and tradeoffs in data organization. Even small implementation decisions mattered because poorly structured logic quickly became difficult to manage as the system grew.

I also used modules like tabulate to present stored data in formatted tables inside the terminal. That might sound like a small detail, but it significantly improved the usability of the system and made the application feel more polished overall.

A large part of the development process was spent debugging logical issues caused by manual data handling. Since everything depended on JSON files, even small structural mistakes could break parts of the system unexpectedly. There were several moments where I had to redesign sections entirely because the previous implementation felt inefficient or difficult to maintain.

But that was also the phase where I started understanding software development differently.

The project stopped feeling like an academic exercise and started feeling like actual engineering — making design decisions, handling limitations, maintaining structure and gradually improving the system through iteration.

Technically, the project was not extraordinarily advanced. But personally, it became one of the most important things I had built at that point because it was the first time I had developed something that felt complete, structured and genuinely usable.
